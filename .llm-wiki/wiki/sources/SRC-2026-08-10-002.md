# AGENTS.md — coding agent guidelines

## Summary

AGENTS.md codifies the structural rules for [[entities/kilat]] so AI coding agents keep new code consistent. It covers the stack (Workers, Hono, D1, Inertia, esbuild, vanilla CSS), layout (`src/server/` flat except `routes/`), 8 hard rules (routes, flat server, SQL in db.ts, env in config.ts, TypeBox validation, TypeScript strict, co-located CSS, design system), route conventions, Workers integration notes (async D1, immutable redirect headers, PBKDF2 cap, no node:crypto, middleware order, static assets binding), testing (`bun test --isolate`), browser testing (console is source of truth), and style.

## Key Takeaways

- **Routes**: one file per URL namespace in `src/server/routes/<feature>.routes.ts`, handlers inline
- **SQL**: all in `db.ts` as async functions — never split by domain under ~600-800 lines
- **Env**: read per-request via `initConfig(env)` — never `process.env` in other modules
- **TypeScript**: `strict` + `noUncheckedIndexedAccess` + `verbatimModuleSyntax` — type-only imports MUST use `import type`
- **CSS**: co-located, not centralised — `styles.css` holds only global base, everything else in sibling `.css` or scoped `<style>`
- **Workers gotchas**: `Response.redirect()` immutable headers, no custom compression, PBKDF2 100K cap, `c.header()` dropped on custom Response
